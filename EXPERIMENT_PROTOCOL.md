# Strict Matched ≥M Experiment Protocol

Version: 1.0
Date: 2026-10-11

This protocol is frozen before any new model training. It does not alter historical multiclass CNN or tabular results.

## 1. Scientific question

Do image-sequence representations and engineered magnetic-feature representations provide different skill for predicting an inherited M/X flare label on the same eligible magnetogram endpoints, under the same active-region-grouped split?

The original dataset label semantics are preserved:

- `AR-flares/general_code/customize_dataset.py:300-328` labels an image when a qualifying flare peak occurs strictly after the magnetogram timestamp and less than 24 hours later.
- A sequence endpoint is the timestamp of `frame_9`.
- The endpoint target is inherited from that final magnetogram label.
- No new event timestamp or horizon is invented.

## 2. Strict common population

The existing `data/*_sequences.csv` files cannot define the strict binary population because `make_sequences.py:46-57` drops all `0` labels before window construction. Those files contain only C/M/X endpoints.

For the strict ≥M experiment, construct a new all-label sequence-endpoint manifest from the existing predefined split files:

- preserve each original Train/Validation/Test split;
- retain labels `0`, C, M and X;
- parse timestamps using the existing filename pattern;
- group by active region;
- sort by timestamp;
- use ten frames;
- use stride 10, matching `make_sequences.py:6-8,67-75`;
- require nine consecutive 12-minute gaps, matching `make_sequences.py:77-96`;
- assign the final frame's inherited label;
- map M/X to target 1 and 0/C to target 0.

This is a new eligible population, not a reinterpretation of the existing C/M/X-only manifests.

The read-only count check found the expected approximate population:

| Split | All-label valid sequences | Active regions | ≥M positive | C/0 negative | ≥M prevalence |
|---|---:|---:|---:|---:|---:|
| Train | 73,278 | 1,253 | 2,264 | 71,014 | 0.0309 |
| Validation | 9,240 | 156 | 271 | 8,969 | 0.0293 |
| Test | 9,165 | 156 | 313 | 8,852 | 0.0342 |

These counts must be regenerated by the implementation script and checked before training. The exact source-of-truth output must be saved and referenced in the checkpoint report.

## 3. Matching key and assertions

Each endpoint must carry:

`split`, `active_region`, `endpoint_filename`, `endpoint_basename`, `endpoint_timestamp`, `frame_0 ... frame_9`, `inherited_flare_label`, `target_ge_m`.

The tabular row must be matched by:

1. exact normalized endpoint basename;
2. exact active-region ID;
3. exact endpoint timestamp;
4. exact split;
5. exact inherited label;
6. identical derived target.

Required assertions before training:

- endpoint key is unique within each split;
- no endpoint key occurs in more than one split;
- all image endpoints have exactly one tabular feature row;
- no tabular row is silently substituted for a missing endpoint;
- zero target disagreements;
- train/validation/test active-region sets are pairwise disjoint;
- image file exists for every frame in every retained sequence;
- all target classes are represented as expected.

## 4. Model branches

### Image branch

The strict image model must include all-label sequences, including 0/C negatives. It must be a binary classifier with:

- same ten-frame input representation;
- same endpoint target;
- binary output probability for M/X;
- train-only fitting;
- validation-only checkpoint selection;
- no test-based architecture or threshold choice.

The existing C/M/X CNN can be evaluated as a secondary baseline by deriving:

`P(≥M) = P(M) + P(X)`

but this is not the strict binary experiment because its training population excludes 0 labels and its optimization target is multiclass C/M/X.

### Tabular branch

The strict tabular model must use the 29 engineered feature values associated with the same endpoint filenames. Candidate primary model: XGBoost with the existing configuration family; logistic regression and other existing baselines may be secondary.

For a strict matched comparison, fit the tabular model on the all-label endpoint-derived training population, not on all 759,357 image-level rows. Existing models trained on the full tabular population may be evaluated on the matched endpoints only as a clearly labeled secondary analysis.

## 5. Threshold and checkpoint protocol

- Fit each model only on matched training endpoints.
- Select the best checkpoint using validation only.
- Select each operating threshold on validation only by maximum TSS over a predeclared grid `0.1, ..., 0.9`, with recall as deterministic tie-break.
- Freeze the selected threshold before test evaluation.
- Do not inspect test metrics to choose a seed, checkpoint, architecture or threshold.
- Report all predeclared seeds; do not select the best seed.

## 6. Required prediction artifact

Every model/seed/split prediction file must contain:

`sample_id`, `endpoint_filename`, `endpoint_timestamp`, `active_region`, `split`, `true_target_ge_m`, `probability`, `predicted_label`, `model`, `seed`, `checkpoint`.

The image artifact must additionally contain:

`frame_0 ... frame_9`, `inherited_flare_label`, `multiclass_probability_C`, `multiclass_probability_M`, `multiclass_probability_X`.

The tabular artifact must include a feature schema/config reference and preprocessing metadata.

## 7. Statistics

Primary test metrics:

- ROC-AUC;
- PR-AUC;
- climatology/no-skill PR-AUC equal to test positive prevalence;
- TSS, HSS, CSI, MCC, F1, precision, recall, specificity and FAR at the frozen validation threshold;
- Brier score and ECE from saved probabilities;
- confusion matrix and normalized confusion matrix.

Uncertainty must be reported separately:

1. Seed mean, sample SD, minimum and maximum.
2. Active-region cluster-bootstrap percentile 95% intervals.
3. Paired active-region cluster-bootstrap intervals for model differences.

For paired comparisons, the same active-region bootstrap draw must be applied to both models on the same matched test rows.

## 8. Historical versus new analyses

Historical results remain under their original paths and must not be overwritten.

- Existing C/M/X CNN results: multiclass, C/M/X-only sequence population, secondary historical result.
- Existing tabular results: full image-level tabular population, binary ≥C/≥M, historical result.
- New strict matched results: all-label sequence endpoints, binary ≥M, same endpoints and active-region splits for both branches.
- Secondary endpoint-subset evaluation: existing full-population tabular model applied to matched endpoints; not a strict matched training comparison.

## 9. Deviations and stopping conditions

Stop before training if:

- all-label sequence generation cannot be reproduced;
- exact endpoint-to-feature matching is incomplete;
- any split contains overlapping active regions;
- image availability is incomplete;
- target disagreements are nonzero;
- the all-label endpoint population differs from the documented audit without a recorded cause.

Do not silently drop unmatched rows. Any exclusion must appear in a machine-readable ledger.

## 10. Reproduction command requirements

The implementation must provide commands that:

1. generate/verify the all-label endpoint manifest;
2. generate/verify the exact matched feature table;
3. train each declared seed;
4. evaluate validation and test splits;
5. export predictions and configs;
6. run statistical aggregation and figure generation.

All commands and outputs will be recorded in `IMPLEMENTATION_CHECKPOINT_3.md` and `RESULTS_README.md`.
